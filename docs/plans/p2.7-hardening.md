## H2 — user-facing correctness

- `add-to-list-control`: catch-revert for a **thrown** server action (only a
  returned `{error}` reverted before — the `toggleSave` idiom it mirrors can't
  hit this, since supabase-js returns rather than throws); house pending guard;
  real error state for a failed `/api/me/lists` (`lists === null` is the
  loading state, so a 5xx stranded the menu permanently); zero-lists copy.
- `AddToListControl` gated on `status === 'published'` — on a draft,
  `collection_items_insert_own` rejects every toggle with no path to success.
- a11y: create-list dialog inputs were placeholder-only (the app's only form
  with no accessible name); report reason `Select` had a blank trigger; the
  report success confirmation was never announced.
- Both lists pages are per-viewer but declared `revalidate = 300`, justified by
  a comment citing `SiteHeaderSession` — a component that no longer exists. Now
  explicit `force-dynamic`. The project page's identical stale comment is
  corrected in place; **its caching is deliberately left alone** (highest-traffic
  page, a real caching decision → Fable).

## H3 — regression nets

`src/lib/meta/source-guards.test.ts` — two source-scanning guards for classes
`pnpm verify` and `pnpm test` are structurally blind to:

1. `'use server'` modules export only async functions (build-only; shipped
   broken in P3-A — `LIST_CAP`/`ITEM_CAP` had to be evacuated).
2. `RESERVED_PROJECT_SLUGS` covers every static dir under `/u/[username]/` —
   a sibling route would otherwise silently orphan a project's permalink.

Both were proven to **fail** against injected instances of their bug before
being committed.
