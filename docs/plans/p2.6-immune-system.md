# P2.6 — Immune system (user reports + AI moderation triage)

## Why

Publish-all (P2.5) removed the human pre-approval gate; the board accepted
that with two backstops promised: a user report mechanism and AI-assisted
moderation. This round ships both. Full execution detail lives in the
orchestrator handoff plan (session plan file); this doc records the shape and
the locked decisions.

## Locked decisions

1. **Deny-all tables** (0009): `project_reports` + `moderation_screens` —
   RLS on, zero policies, zero grants. All access is service-role behind
   `reportProject()` / `requireAdmin()` / the cron pipeline. Reports are
   moderation-sensitive: client-write-under-RLS (the saves pattern) would be
   forgeable and brigade-visible.
2. **AI is triage-only.** Verdicts (`ok`/`review`/`flagged` + reason) label
   and order the admin queues; AI never unpublishes. docs/vision.md permits
   reversible AI unpublish — deliberately unused until verdict quality is
   proven on real data.
3. **Budget ceiling unchanged**: ≤8 AI calls per pipeline run.
   `ENRICH_PER_RUN` 8→5, `SCREEN_PER_RUN` 3. Pass order: materialize →
   enrich → **screen** → sync backfill (safety before cosmetics).
4. **Stamping discipline** (P2.1 lesson): systemic failures
   (rate_limited/config/provider_error) stop the batch WITHOUT writing;
   genuine-but-unparseable replies stamp `verdict:'review'` with a synthetic
   reason (never silent-ok, never infinite retry).
5. **One screen per project** (PK project_id, upsert-overwrite). Re-screen
   when an open report is newer than the screen row. Report-triggered screens
   outrank retro-backlog screens; `source:'report'` wins dedupe.
6. **Report constraints**: unique (project, reporter) for life (no re-report
   path, accepted v1); ≤5 reports/profile/24h; no self-reports; published
   projects only.
7. Retro-queue screening filters on **live `projects.stars_count`** (same
   population the admin retro section shows), not the candidate's stale
   snapshot.

## Shape

- **0009_immune_system.sql** — both tables + open-reports partial index.
  Suites: rls_checks_ingestion I8–I12 (deny-all + constraint behaviors),
  rls_checks §3b (zero-policy assertion; the 23-policy inventory is
  unchanged — deny-all adds none).
- **Report flow**: `src/lib/moderation/report-policy.ts` (pure rules) →
  `reportProject` server action (service-role writes, rate limit, 23505 →
  friendly "already reported") → `ReportButtonIsland` dialog in the project
  page action row (signed-out → signin redirect, toggleSave idiom).
- **Screen engine**: `src/lib/ai/moderate.ts` (prompt + strict parse, pure)
  + `src/lib/enrich/screen.ts` (`screenNextBatch` — two-priority queue:
  reported first, retro backlog second; enrichNextBatch pacing/deadline/
  stopKind semantics). `gateway.ts` `ChatCompletionOk` gains `model` for
  screen provenance.
- **Pipeline**: pass 3 screen (≤3/run), response adds
  `screened`/`flagged`/`screenStopKind`.
- **Admin queue**: reports section (grouped by project, verdict chips,
  resolve / unpublish / delete+block) above the retro section; retro rows
  sort flagged → review → unscreened → ok.

## Not in this round

Auto-unpublish on flagged verdicts (see decision 2) · report UI anywhere but
the project page · notification/email on reports · re-report after resolve.
